# 实验降本原则与 API 费用记录

## 已确定的运行原则

组件 1 恢复一个复现目标；组件 2 依次适配三个检索测试，每个测试最多五轮。一个候选被严格验证器接受后，只结束该候选的迭代，另外两个仍会执行，最后按既有规则选择一个 BRT。

为了降低费用，优先消除重复计算和故障后的无效工作。不能把减少候选、五轮降三轮、首个接受就结束整个实例称为无损优化；这些修改需要另做效果验证。独立重复实验不能复用上一次的模型采样响应。

已确认的运行问题与处理方向：

1. 接口异常与合法 KEEP 分开：余额不足不应变成 KEEP，更不能据此复制不完整父测试或启动备用适配。
2. 按候选、按轮次恢复：复用同一次实验中完整保存且输入、模型和配置一致的成功步骤；不能只看顶层 ISSUE_ALIGNED_FAIL 就断言三个分支都完整。
3. 根据真实 token 用量分析输入、输出和重试成本，再决定提示词去重及调用合并是否值得验证。

第一轮实现了费用记录。随后补齐了接口故障隔离和同一次实验的分步续跑，见下节。候选数量、迭代预算、正式提示词、严格验证接受条件和排序策略保持不变。

后续对“提示词去重、合并验证与下一轮规划”做了独立小实验：95 组历史记录的离线核对，以及三个冻结检查点的四组真实请求对照。正式流程未启用这些实验变体。去重直接减少输入 token 约 0.46%；所测合并原型存在计划缺失后的回退开销，未证明稳定降本。未运行这一变体的官方 F2P 评测，不能声称效果保持。完整记录见 [最小验证报告](../analysis/prompt_cost_pilot_20260918/报告.md)。

## 接口故障隔离与分步续跑

接口超时、网络故障、耗尽重试次数，以及不完整/空响应在重试后仍未解决时，抛出独立的 `LLMUnavailableError`。规划器和验证器不把它转换成 KEEP、测试失败或新的修复指令。

- 明确的余额/账户额度不足：当前进程停用该接口，并轮换到其他可用接口。
- 普通限流、网络失败：沿用有界请求重试，在本次请求内优先切换到尚未尝试的接口；不把普通 429 当作余额耗尽。
- 请求仍未完成：实例记为 `PAUSED_API`。尚未开始的实例停止排队执行，已经在运行的请求正常收尾或记录中断。
- 命令行返回 75，阶段保存 `api_paused.json`。全量启动脚本停止，不因 API 故障进入备用适配、最终排序或官方评测。退出时仍汇总 API 用量。

使用相同实验目录和 `--resume` 可恢复。每个候选在自己的 `.resume` 目录记录成功的模型响应、父测试执行和候选执行观察；三个候选分别恢复。只有完整完成的实例才能整体跳过。API 已完成而 JSON 修复请求中断时，恢复会复用原响应，只补修复请求。

复用按调用顺序和完整输入比较，不按提示词相同就合并两个独立采样。身份包含 Issue、检索输入、规范内容、模型配置、运行参数和实际代码/提示词快照；不使用哈希。不同输入、参数或代码不复用旧步骤；当前步骤输入变化时，后续旧记录被归档。显式指定的规范缓存优先于输出目录里的旧副本，避免恢复时误读旧输入。

完成状态还检查最终代码和排名文件内容。没有新版步骤记录的历史结果不能仅凭一个顶层 `ISSUE_ALIGNED_FAIL` 视为完整三候选结果，也不会自动导入为新版续跑记录。新独立实验应使用新目录；充值或服务恢复后启动新的进程，已停用接口会重新参与请求。

本次离线故障注入使用真实三候选反馈控制流程、模拟模型及执行返回值：不中断需要 9 次成功请求；第 6 次请求发生超时后，续跑只需补 4 次，先前 5 次成功请求没有重发。最终测试代码、选中候选和各候选排名与不中断运行一致。还检查了组件 1 的 JSON 修复中断、输入变化和最终文件变化后的失效处理。

这验证的是减少故障造成的重复调用，没有测量新的官方 F2P，也没有证明总费用一定下降某个比例。回放仅适用于同一次实验的同一仓库版本和环境；它不会恢复测试对外部服务或持久状态造成的副作用。服务端已计费但响应尚未完整保存时，仍可能需要重新请求。原子写入防止半截记录被当成完成结果，不承诺机器断电时所有尚未落盘数据都能保存。

没有启用提示词去重或合并验证与规划，也没有启动新的付费实验。

上述降本修改后的启动检查另发现英文协议审查模板的 JSON 大括号未转义，
使该步骤在发出请求前失败。随后已修复格式并补充回归测试，真实接口短重试
成功。该修复恢复原有协议审查调用，可能改变后续协议信息并增加相对旧故障
路径的调用成本，不能与“断点续跑减少重复请求”的证据混为一谈，也未据此
宣称 F2P 不变。

## 每次实验保存的文件

全量、通用全量/消融及三例预检启动脚本会把费用文件写入各自 RUN_DIR：

```text
api_requests.jsonl       每次 HTTP 请求的开始与结束事件，只追加
api_cost_summary.json    机器可读汇总，包括总费用、用量、重试和分组统计
api_cost_summary.md      中文费用摘要
logs/api_cost.log        退出时汇总命令的输出
```

账本按每次实际请求统计。截断后重新请求，两次均记录；正常断点续跑继续追加，不覆盖前次费用。同一请求的开始和结束事件按随机请求标识合并，不重复计费，不使用哈希。

汇总包含：请求尝试数、逻辑调用数、重试数、输入和输出 token、缓存输入 token、推理 token、已知金额小计、未知金额请求数，以及按组件、调用模块、实例和请求模型分组的统计。推理 token 作为输出明细保存，不再次加进输出计费。

系统不在费用账本里保存 Key、完整请求地址、提示词或模型生成内容。账户余额不是本实验费用，其他进程的消费不能算到本实验头上。

## 金额从哪里来

优先采用明确配置的接口账单金额字段；否则使用接口返回的 token 和用户填写的单价估算。系统不猜测供应商价格，也不把余额拒绝、超时、缺失用量当作免费。

定价模板在 `config/llm_pricing.example.json`。先复制到本地，再填写自己账户的实际单价：

```bash
cd /root/Baxxhy/BugReproduce/brt6
cp config/llm_pricing.example.json .secrets/llm_pricing.json
# 编辑 .secrets/llm_pricing.json，填写实际价格。
export BRT_LLM_PRICING_FILE=/root/Baxxhy/BugReproduce/brt6/.secrets/llm_pricing.json
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| host / model | 精确匹配供应商域名和请求模型，不自动假设模型别名同价 |
| currency | 价格使用的币种，例如 CNY |
| input_per_million | 每百万输入 token 的金额 |
| output_per_million | 每百万输出 token 的金额 |
| cached_input_per_million | 缓存命中的输入价格；如果输入统一价格则留 null |
| reported_cost_field | 接口实际金额的 JSON 路径；只有确认该字段是此币种的金额才填写，不能填额度单位 |

`null` 表示未知，不是零价格。已知免费才填写数值 0。配置了缓存差异价格但接口不返回缓存用量时，金额也保持未知。

每条账目保存当时使用的价格。后续修改价格不追溯改写已记录的金额。多个币种分别汇总，不做未经配置的汇率换算。

只有所有已记录请求金额都可计算且币种一致时，`total_cost` 才是一个数值；否则为 null，同时报告已知金额小计及缺口。`reported` 表示接口报告金额，`estimated` 表示估算，`mixed` 表示两者混合。**只返回 token、没有单价配置，就只能保存用量，不能得到可信的货币总额。**

## 自动汇总与手动查看

以下入口自动接入：

- `scripts/run_trait_xiaojing_deepseekv4flash_full.sh`
- `scripts/run_p0_simple_llm_selector_full.sh`（含消融）
- `scripts/run_xiaojing_deepseekv4flash_smoke3.sh`
- `python -m brt6.pipeline.run_issue_rewrite` 和 `python -m brt6.pipeline.run`：单独使用时写入各自 output_dir；指定 BRT_COST_DIR 则统一记到该实验目录。

其他自定义实验在启动前设置：

```bash
export BRT_COST_DIR=/root/Baxxhy/BugReproduce/brt6/results/runs/你的实验目录
```

采用同一个 LLMClient 的请求会进入此目录。直接调用其他 SDK 或 curl 的请求不在统计范围内。请求时逐次保存账本，Python 正常退出和上述脚本退出时汇总。强制杀进程或服务器断电时，未完成请求的金额可能未知，可重建已保存账本的汇总：

```bash
/root/miniconda3/envs/icore/bin/python scripts/summarize_api_cost.py \
  --run-dir /root/Baxxhy/BugReproduce/brt6/results/runs/你的实验目录
```

如果当时没有价格、但 token 已保存，可补算原来未知的条目：

```bash
/root/miniconda3/envs/icore/bin/python scripts/summarize_api_cost.py \
  --run-dir /root/Baxxhy/BugReproduce/brt6/results/runs/你的实验目录 \
  --pricing-file /root/Baxxhy/BugReproduce/brt6/.secrets/llm_pricing.json
```

这里的总费用仅包括账本启用后、此目录记录的 API 请求。复用历史组件 1 结果时，本轮费用不会重新计入它的历史生成成本；论文报告从零端到端成本时必须另计这些成本。旧实验只有提示词和响应文件、没有完整用量与账单时，不能从文件数量反推精确花费。

## 本次验证边界

采用本地模拟接口验证正常响应、流式响应、截断重试、余额错误、缺失用量、并发写入、恢复累计及价格补算。验证不调用付费模型，不启动 Docker 或全量实验。实际供应商的计费精度仍取决于其返回的用量、账单字段及所配置的实际价格。
