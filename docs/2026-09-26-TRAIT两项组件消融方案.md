# TRAIT 两项组件消融方案与运行说明

日期：2026-09-26。本文只规定实验与运行方式，不启动生成或评测。环境已安装。

## 1. 两项独立实验

不是同时删除两个组件，而是分别与同一 Full 比较。

| 项目 | Full TRAIT | w/o C1 | w/o C2 |
|---|---|---|---|
| 原始 issue、仓库代码、相同 Top-3 检索测试 | 保留 | 保留 | 保留 |
| C1 复现目标恢复 | 保留 | 删除 | 保留 |
| C1 主目标和按需备选目标 | 使用对照版本的机制 | 全部删除 | 保留同版本机制 |
| 每个父测试的独立适配 | 保留 | 保留 | 删除 |
| Semantic Delta 规划和更新 | 保留 | 保留 | 删除 |
| preserve/change/avoid、定向修复策略 | 保留 | 保留 | 删除 |
| 普通生成、执行、反馈修复 | 作为适配流程的一部分 | 同 Full | 作为 C2 的替代流程 |
| 验证成功标准、最终选择、官方评测 | 同版本 | 同版本 | 同版本 |

组件1是 Reproduction Target Recovery；组件2是 Individual Test Adaptation。完整去掉组件2意味着去掉其特有的独立适配和语义规划机制，不是停止生成测试。

## 2. w/o C1：直接以原始 issue 驱动独立适配

```text
原始 issue + 仓库上下文 + 相同检索测试
→ 三个父测试分别适配
→ Semantic Delta + 迭代反馈
→ 相同校验与选择
→ 官方 F2P
```

唯一组件开关为 `--enable_behavior_target false`。保留 `--enable_seed_mutation true`、`--enable_semantic_delta true` 和原有反馈配置。不传 `--behavior-target-cache`，不读取 Full 的目标文件或备用目标。

具体参数、三例预检、全量生成、选择、评测命令见 [消融组件1运行文档](2026-09-26-TRAIT消融组件1运行文档.md)。模型通过 `MODEL` 与 `PROVIDER` 指定，与 Full 一致。

必须检查：

- 输出 `ablation_id=wo_behavior_target` 和 `behavior_target_enabled=false`。
- 保存原始 `raw_issue_context.json`，没有目标恢复请求或目标缓存输入。
- 仍保留三个独立适配分支及 Semantic Delta。
- 提示词仍包含完整原始 issue 和对应仓库上下文。

不能复用 Full 的生成候选后仅重新排序；需要在没有 C1 信息的条件下重新生成。

## 3. w/o C2：用普通生成组件替换 C2（沿用历史实验）

按用户确认，直接沿用当时的 **C1 + 普通生成 + 普通执行反馈** 实验定义，不重新设计另一种 C2 消融。普通生成组件接收原始 issue、C1 目标、仓库上下文和联合 Top-3 测试；不以某个父测试为适配起点，也不使用 Semantic Delta。

```text
原始 issue + 仓库上下文
→ 保留 C1 的复现目标
→ 将相同 Top-3 测试放入一个共享上下文
→ 普通生成三个候选，每个候选使用相同共享上下文
→ 各候选按实际执行日志进行普通修复
→ 相同校验成功标准与最终选择
→ 官方 F2P
```

### 3.1 完整删除范围

删除指定单个父测试作为适配起点、父子差异规划、Semantic Delta 更新、preserve/change/avoid、next_operator、语义残差驱动的分类修复提示，以及通过这些字段控制修改范围的逻辑。验证器保留对 issue 对齐与真实执行的检查，但不再输出语义规划，也不将其传回生成器。

普通反馈只提供候选代码、实际 stdout/stderr、执行状态及验证结论/原因。模型直接修改当前候选。每个候选仍有自己的反馈历史，这是防止日志串线的基础运行要求，不是“独立父测试适配”。

保留仓库原生测试位置、runner 和必要 fixture 的运行支持，不能通过破坏环境使消融变差；这些信息用于运行，不得暗中指定必须保留某个父测试的逻辑。

三份候选是三个共享上下文下的生成尝试，不是“一次只生成一个”或“分别适配三个父测试”。若 Full 有额外兜底，保留相同触发条件和预算，但兜底也必须使用普通生成，不能重新启用 C2。

### 3.2 已提交的历史普通生成入口

历史普通生成实现已保存到 `ablations/plain_generator/brt6/`，来源为本机2026-09-24 GPT普通生成实验的代码快照。算法与提示词逐字节保留，不再依赖旧 results 目录。运行输入、凭据和评测环境使用当前仓库已有文件；这些外部文件没有复制进快照。

入口是 `scripts/run_plain_generator_ablation.sh`，模型必须显式传入。下面在已有环境中运行，先将 TARGET_CACHE 换成对应 Full 的有效冻结 C1 缓存：

```bash
cd /root/Baxxhy/BugReproduce/brt6
export MODEL=gpt-5.4-mini
export PROVIDER=gpt
export BRT_API_POOL_FILE="$PWD/.secrets/api_pool.json"
export TARGET_CACHE=/root/你的Full实验/behavior_target_cache
export RUN_DIR="$PWD/results/runs/wo_c2_${MODEL}_$(date +%Y%m%d_%H%M%S)"
export MAX_SEMANTIC_ROUNDS=6
bash scripts/run_plain_generator_ablation.sh
```

DeepSeek 改为 `MODEL=deepseek-v4-flash PROVIDER=deepseek`，并使用对应 Full 的 C1 缓存。脚本先跑数据集顺序前三例，通过流程检查后继续276例、排序和官方F2P评测，生成/评测并发20。日志位于 `$RUN_DIR/logs/`。续跑使用原 RUN_DIR 与所有原参数。

这是历史普通生成实现的可携带入口，不是当前 Full 算法的自动等价转换。与新 Full 比较前须核对代码、反馈轮数、模型设置及基础设施版本差异。当前主 pipeline 的两个关闭开关仍不能代替这个专用入口。

### 3.3 复用普通生成组件时的配置与核验

模型、provider、数据文件、代码/测试检索文件、C1 缓存、候选数、反馈轮数、输出目录和并发均由参数传入，不能写死模型。运行清单记录 `reference_mode=joint_top3`、`individual_adaptation=false`、`semantic_delta=false` 和 `feedback=ordinary_execution`。

可复用同模型、同输入、同版本 Full 的 C1 缓存，省掉重复调用；同时保留原始 issue 与仓库上下文。若缓存缺失或身份不一致，先补齐 C1，不能悄悄退化为无 C1。备用目标若按失败触发，应继续遵循该版本触发规则，而非复制 Full 的触发结论。

先使用数据集顺序前三例做流程预检，不按历史 F2P 挑样本：

1. 三个生成尝试均收到相同 Top-3 测试集合及 C1 目标。
2. 不请求 Delta planner，不生成 Delta 文件，不向模型注入残留的 preserve/change/avoid 或 next_operator。
3. 各候选反馈对应自身实际执行记录；未发生零测试当成功、旧日志复用或环境错误触发无效修复。
4. 最多初始生成一次加五次反馈，与对应 Full 的轮数相同；候选接受后按相同规则停止。
5. 校验、排序与官方评测的实现和 Full 一致。校验提示只去掉修复规划部分，不顺便放宽接受标准。

预检通过后运行全部276例，输出冻结后统一评测。三例检查只证明接线正确，不设置“必须比 Full 差”的分数门槛。

## 4. 公平控制与复用范围

两项消融均固定模型、推理档位、温度、候选数、反馈上限、检索结果、运行环境和选择规则。推荐沿用对应 Full 配置：生成并发20、评测并发20、只计算 F2P。当前六轮表示初始一次加五次反馈；对照若只有五轮总次数，不能单方面增加消融预算。

可复用检索和镜像。w/o C1 不可复用 C1 的目标、候选或 Delta；w/o C2 可以复用符合身份条件的 C1 输出，不可复用已适配候选作为普通生成的起点。fixed、gold patch 和官方结果仅用于输出冻结后的独立评测。

完整方法与消融的实际 API 调用数不必相等：删除目标恢复或规划本来就节省调用。固定生成机会并报告实际成本，不为了凑同样花费额外生成。对主备目标及兜底带来的预算差异单独记录。
