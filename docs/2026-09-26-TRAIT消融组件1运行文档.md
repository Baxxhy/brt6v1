# TRAIT 消融组件1：w/o Reproduction Target Recovery

日期：2026-09-26。本文假定本机已有运行环境、SWT276数据、检索结果和API配置。只说明如何运行；本次写文档没有启动实验。

## 1. 消融的定义

本实验回答：**在保留原始issue和相同仓库上下文的条件下，显式复现目标恢复是否帮助后续独立测试适配？**

完整方法：

```text
原始issue + 仓库上下文
→ C1恢复复现目标（以及该版本支持的按需目标处理）
→ C2对相同的三个检索测试分别进行适配
→ Semantic Delta + buggy执行 + 分类反馈 + 严格校验
→ 相同选择规则
→ 每个实例一个最终BRT
→ 官方F2P评测
```

消融方法：

```text
原始issue + 同样的仓库上下文
→ C2直接以原始issue为依据，分别适配相同的三个检索测试
→ Semantic Delta + buggy执行 + 分类反馈 + 严格校验
→ 相同选择规则
→ 每个实例一个最终BRT
→ 官方F2P评测
```

**只去掉C1，不能同时去掉Semantic Delta、独立适配、原始issue或仓库代码。** 没有BehaviorTarget时，Semantic Delta仍比较父测试场景与原始issue要求；不再输入C1加工后的结构化目标。

代码开关是 `--enable_behavior_target false`。当前实现直接构造 `RawIssueContext`，不调用目标恢复，也不读取目标缓存，并保存 `raw_issue_context.json` 和 `behavior_ablation_manifest.json`。内部消融标识是 `wo_behavior_target`。

C1中的主/备目标均属于移除范围。C2保留其原有直接适配流程；不能额外给消融组加一轮重试以补回C1省下的预算。若Full包含额外目标分支，须在论文中报告两组实际分支、调用次数和花费；该比较衡量整个C1的作用，不应声称仅隔离了目标JSON的表达形式。

## 2. 必须与Full固定的条件

| 条件 | 本文命令的设置 | 比较要求 |
|---|---|---|
| 数据 | SWT-Lite 276例 | 完全相同实例、base commit、issue |
| 模型 | 显式传入MODEL、PROVIDER | 与对应Full一致，不能拿GPT消融对比DeepSeek Full |
| 检索 | 相同code/test检索文件 | 相同内容和排序 |
| 检索输入上限 | top_code=6、top_tests=5 | 本地当前默认；不是五个适配分支 |
| 独立适配分支 | 当前代码取检索顺序前3个 | 保持Full同一选择逻辑 |
| 轮数 | max_semantic_rounds=6 | 初始生成1次＋最多5次反馈；历史Full若为5轮须改成5 |
| 温度 | 0.1 | 对照Full清单，不凭记忆设置 |
| 基础输出预算 | 4096 | 与Full一致；GPT生成阶段当前代码会单独提高预算 |
| 验证 | strict、buggy_only | 不额外调用Issue2Test judge |
| 选择 | 当前strict-iCoRe脚本 | 两组必须同一版本 |
| 并发 | 生成20、评测20 | API池采用相同设置 |
| 超时 | API1200秒、Docker7200秒 | 与Full一致 |
| 评测 | 官方SWT，coverage关闭 | 分母固定276，缺提交也计入 |

GPT使用`PROVIDER=gpt`；DeepSeek使用`PROVIDER=deepseek`。当前代码对GPT生成步骤显式使用low reasoning，不能因为设置`BRT_DISABLE_THINKING=1`就声称所有GPT步骤无推理；两组应使用相同代码和推理设置。

**旧脚本 `scripts/run_trait_wo_c1_full.sh` 不作为本文入口。** 它仍把DeepSeek模型写死，部分记录写5轮而实际默认6轮。本文直接调用参数化pipeline，避免这些差异。不需要修改算法。

## 3. 设置本次参数

在同一个终端依次执行。先将模型、API池和输出目录改成自己要跑的配置；API池内须有对应provider的可用配置，不要把key直接放进命令。

```bash
cd /root/Baxxhy/BugReproduce/brt6

# GPT示例。改DeepSeek时同时改成 deepseek-v4-flash / deepseek。
export MODEL=gpt-5.4-mini
export PROVIDER=gpt
export BRT_API_POOL_FILE="$ROOT/.secrets/api_pool.json"

# 每个模型、每个消融使用新目录。续跑时保留完全相同的目录和参数。
export RUN_DIR="$ROOT/results/runs/trait_wo_c1_${MODEL}_$(date +%Y%m%d_%H%M%S)"
export GENERATION="$RUN_DIR/design2_individual_adaptation"
export SELECTION="$RUN_DIR/strict_icore"
export EVALUATION="$RUN_DIR/evaluation/official_f2p"
export MAX_SEMANTIC_ROUNDS=6

export PYTHONPATH=/root/Baxxhy/BugReproduce
export BRT_MODEL_ID="$MODEL"
export BRT_ALLOWED_API_HOST=api.open.xiaojingai.com
export BRT_DISABLE_THINKING=1
```

## 4. 先跑3例，确认消融生效

以下数组既用于预检，也用于全量，防止两套命令发生参数偏移。不要传`--behavior-target-cache`。

```bash
GEN_CMD=(
  "$PYTHON_BIN" -u -m brt6.pipeline.run
  --instances_path "$ROOT/data/issues/swt276_issues.json"
  --code_retrieval_path "$ROOT/retrieval_results/code/code_retrieval_results_gpt.json"
  --test_retrieval_path "$ROOT/retrieval_results/test/icore/gpt/related_tests.json"
  --repo_root_base /root/Baxxhy/BugReproduce/swe_repos
  --output_dir "$GENERATION"
  --model "$MODEL" --llm-provider "$PROVIDER"
  --top_code 6 --top_tests 5
  --temperature 0.1 --max_tokens 4096 --max_workers 20
  --max_semantic_rounds "$MAX_SEMANTIC_ROUNDS"
  --timeout 7200 --resume
  --validation_mode buggy_only --alignment-verifier strict
  --dataset_mode swt --runtime_backend official_docker
  --official_harness_python "$SWTBENCH_PYTHON"
  --swtbench_root "$ROOT/evaluation/vendor/swtbench"
  --enable_behavior_target false
  --enable_protocol_recovery true
  --enable_seed_mutation true
  --enable_semantic_delta true
  --enable_specialized_feedback true
  --enable_environment_feedback true
  --enable_trigger_feedback true
  --enable_assertion_feedback true
  --enable_strict_semantic_verifier true
)

"${GEN_CMD[@]}" --limit 3 > "$RUN_DIR/logs/pilot_generation.log" 2>&1
```

预检只检查接线和配置，不要求这3例F2P高或低。检查输出：


还应检查预检中确有buggy执行记录，没有持续的容器错误、零测试误判或API错误。API暂停不能当作候选失败。若检查失败，修复运行问题后在本目录续跑，不换数据挑容易成功的实例。

## 5. 全量生成、选择和评测

保持上述终端变量和GEN_CMD数组。建议在已有tmux会话中运行，避免SSH断开；本文命令本身是前台顺序执行。

### 5.1 生成

```bash
"${GEN_CMD[@]}" > "$RUN_DIR/logs/generation.log" 2>&1
```

这次不带`--limit 3`，处理全部276例。`--resume`只复用本消融目录下配置匹配的预检输出。检查总汇总与日志，确认所有实例均已结束；未生成可提交测试与API/基础设施尚未完成必须分别统计。

### 5.2 选择最终BRT

```bash
"$PYTHON_BIN" -u "$ROOT/scripts/run_generation_strict_icore.py" \
  --generation "$GENERATION" \
  --output "$SELECTION" \
  --issues "$ROOT/data/issues/swt276_issues.json" \
  --workers 20 > "$RUN_DIR/logs/selection.log" 2>&1
```

该步骤使用生成阶段已有strict判断和当前iCoRe选择逻辑，不重新调用Issue2Test judge。没有accepted候选时仍按同版本规则处理可用候选，不能为了让消融变差丢弃提交。

### 5.3 官方F2P评测

```bash
"$SWTBENCH_PYTHON" "$ROOT/scripts/run_official_eval_after_generation.py" \
  --dataset swt \
  --outputs-dir "$SELECTION/generation" \
  --dataset-file "$ROOT/data/official/swt276_official_eval.json" \
  --official-dataset-name "$ROOT/data/official/swt276_official_eval.json" \
  --evaluation-dir "$EVALUATION" \
  --max-workers 20 --timeout 7200 \
  --run-id "$(basename "$RUN_DIR")" \
  --model-name "trait-wo-c1-$MODEL" \
  --compute-coverage false \
  --official-python "$SWTBENCH_PYTHON" \
  --swtbench-root "$ROOT/evaluation/vendor/swtbench" \
  > "$RUN_DIR/logs/evaluation.log" 2>&1

"$PYTHON_BIN" "$ROOT/scripts/summarize_api_cost.py" --run-dir "$RUN_DIR" \
  > "$RUN_DIR/logs/api_cost.log" 2>&1

cat "$EVALUATION/metrics.json"
```

fixed/gold数据仅交给独立官方评测；不输入生成、验证或排序。当前命令不计算覆盖率。模型花费若缺供应商价格，只报告可核实token/调用数及价格缺失，不把未知成本写为0。

## 6. 哪些能复用，哪些不能

可复用：同一数据集、原始issue、已有代码/测试检索结果、buggy仓库、Docker镜像与环境缓存。

不可直接复用：Full的BehaviorTarget、C1备用规范、C1改写后的issue、基于这些目标生成的Semantic Delta和候选，以及Full的选择结果。

**w/o C1需要重新生成C2候选。** 给Full输出删掉一个target文件后重新rank，测不到“没有C1时C2会生成什么”，不能作为该消融。正式评测完成后，完全相同的候选和环境可复用已有逐例评测，但不能依据fixed成功与否选择历史版本。

## 7. 论文如何展示

消融名称推荐 **w/o Reproduction Target Recovery**，括号注明w/o C1。研究问题：显式目标恢复对最终BRT生成有效性与成本的贡献。

| Variant | F2P / 276 | F2P (%) | API calls / issue | Total API cost |
|---|---:|---:|---:|---:|
| Full TRAIT | 实测 | 实测 | 实测 | 实测 |
| w/o Reproduction Target Recovery | 实测 | 实测 | 实测 | 实测 |

同时报告Full成功而消融失败的实例数，以及消融成功而Full失败的实例数。百分点差为 `(Full成功数 - 消融成功数) / 276 × 100`，不要混成相对百分比。

同一模型单独一组比较。历史Full只有当代码、模型、输入和预算与本轮控制条件一致时才能直接作为对照；不一致则明确标为探索性比较，不能声称单因素因果效果。若旧Full只有初始＋4次反馈，消融也用5轮，不要单方面给消融组6轮。

不能预设消融一定更差。若差距小、持平或反向，先检查C1是否真的关闭、原始issue是否仍保留，以及预算/环境是否一致；检查无误后如实报告。不能通过减少消融预算或提高拒绝门槛制造差距。
