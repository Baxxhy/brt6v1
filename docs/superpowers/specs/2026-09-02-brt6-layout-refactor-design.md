# BRT6 目录与入口重构设计

## 目标

将实际源码从 `/root/Baxxhy/BugReproduce/brt6/brt6` 上移到
`/root/Baxxhy/BugReproduce/brt6`，让这个目录直接成为 BRT6 项目根目录；同时
统一当前代码、测试、脚本和运行文档中的包名与入口，保持算法、提示词、默认参数、
输入输出格式以及官方 Docker/Conda 运行契约不变。

## 当前问题

- 项目根目录多套一层同名目录，导致从不同工作目录执行时包导入和脚本路径容易混淆。
- 功能实现已经分在 `core`、`llm`、`issue`、`context`、`generation`、`execution`、
  `validation`、`evaluation` 等目录，但根目录兼容包装器、`runtime`/`retrieval`
  兼容层和历史文档没有明确标注边界。
- 当前入口仍有 `brt4`、`brt5`、`BRT3` 的历史残留；部分测试和辅助脚本因此导入错误的
  包名，运行说明也不能直接复制执行。

## 设计

1. **单一项目根目录**：上移嵌套目录的全部内容，包括隐藏文件；上移后保留
   `brt6/__init__.py`，使项目根目录本身就是 Python 包目录，运行时从其父目录导入
   `brt6`。
2. **功能包优先**：真实实现继续放在现有功能包中；根目录的一行模块只作为兼容入口，
   不删除、不改变其导出的对象。`runtime` 和 `retrieval` 的转发模块也保留，因为它们
   是已有调用方使用的导入路径。
3. **名称分层**：用户可见的包导入、CLI 模块、脚本和文档统一为 `brt6`；缓存 schema、
   环境名前缀、历史环境变量（如 `brt5i_*`、`BRT4_*`）属于持久化/兼容契约，本轮保留，
   避免破坏已有缓存、环境和恢复结果。
4. **运行文档单一入口**：`README.md`、`README_RUN.md`、`README_STRUCTURE.md` 和
   `README_REPRODUCE.md` 使用 BRT6 路径和命令，并明确区分“静态检查/小测试”与会调用
   LLM、Docker 或正式实验的命令。
5. **验证边界**：只执行 Python 编译、离线单元测试、shell 语法检查和 CLI `--help`；
   不启动真实模型请求、官方 benchmark 容器、全量生成或评测。

## 不在本轮范围

- 不调整生成、反馈、验证、评测算法或提示词语义。
- 不改变默认模型、温度、worker 数、候选数、超时、结果目录和 JSON 字段。
- 不重命名已有运行缓存、Conda 环境、历史结果或持久化 schema。
- 不删除历史文档；只在其标题和当前入口描述中标明 BRT6，避免把历史记录误当作当前
  入口。

## 验收标准

- `/root/Baxxhy/BugReproduce/brt6/brt6` 不再存在，项目根目录直接包含包文件和文档。
- 当前测试与辅助脚本只通过 `brt6.*` 访问本项目实现；保留的 `brt5`/`brt4` 文本仅限
  明确的历史或持久化兼容契约，并有注释/文档说明。
- 运行说明中的命令从项目父目录执行，不依赖当前机器上的其他 BRT checkout。
- Python 编译、shell 语法、离线测试和 CLI help 验证均有新鲜输出；没有启动真实实验。
