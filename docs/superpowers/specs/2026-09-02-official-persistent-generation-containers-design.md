# 官方生成容器常驻复用设计

## 目标

SWT-Bench 生成阶段必须使用官方 harness 产生的完整容器名称，并与评测阶段按实例复用同一个常驻容器。生成结束不得删除容器或官方实例镜像。同时，生成运行记录必须保存实际配置的并发数。

## 边界

- 只调整 SWT-Bench 生成容器的命名、登记、互斥和关闭策略，以及生成并发元数据。
- 不改变数据集、官方镜像名称、镜像内容、测试命令、补丁、覆盖率和评分逻辑。
- TDDBench 现有生命周期不在本次修改范围内。
- 不启动正式生成或评测。

## 容器身份与登记

首次为实例创建容器时，调用官方 `ExecSpec.get_instance_container_name()` 取得完整 `exec.eval...` 名称，不追加 BRT 自定义后缀。创建成功后，将实例 ID、官方容器名和官方实例镜像名写入项目内 `.runtime/official_container_registry.json`。

后续生成和评测先查登记表，再按容器名读取 Docker 对象。只有名称、镜像和容器健康状态全部匹配时才复用。登记缺失时允许登记唯一且兼容的官方容器；同一实例或镜像存在多个候选时不猜测，直接输出诊断错误。登记表采用文件锁与原子替换，支持多实例并发更新。

## 并发与隔离

生成和评测共用 `.runtime/locks/<instance>.lock`。锁覆盖单个实例的一整段容器使用期，避免生成与评测同时修改同一工作区；不同实例仍可并发。每次执行命令前继续使用现有逻辑将 `/testbed` 重置到数据集 base commit 并清理生成文件，防止跨候选和跨阶段污染。

## 生命周期

- 正常关闭：写回运行清单，释放实例锁，保留容器和官方实例镜像。
- 已退出容器：启动后复用。
- 镜像不匹配、容器 dead 或元数据冲突：拒绝复用并报错，不自动删除用户容器。
- 启动过程中尚未完成登记的新容器失败：只清理由本次尝试创建且已明确记录的对象。
- 运行清单记录容器为 persistent、是否复用、登记表路径及关闭后的状态。

## 并发元数据

`run_config.json` 写入 `max_workers`；`summary.json` 将实际传入的 `args.max_workers` 记录为配置值，同时保留单独的默认值字段，避免再把默认值误当成实际值。

## 验证

自动化测试覆盖：官方原名首次创建、登记后的跨运行复用、错误镜像拒绝、重复候选拒绝、正常关闭不删除容器与镜像、失败启动只清理本次对象、实例锁释放，以及实际并发写入两个元数据文件。最后运行相关测试、完整单元测试和 Python 编译检查；不执行正式生成或评测。
