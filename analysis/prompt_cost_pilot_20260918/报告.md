# 提示词去重与合并规划：最小验证结果

## 决策

**保留正式流程，不默认启用这两项改动。** 所测去重实现的直接输入节省很小；合并原型减少了部分调用，但没有减少总 token。没有重新生成测试，没有运行官方 F2P 评测，不能声称 F2P 保持或提升。

此次完成的是降本机制的第一阶段筛查。在尚未看到明确成本收益时，不追加生成与 Docker 成本。该结果不代表所有提示词压缩或合并方案均无效。

## 实验配置与范围

- 来源：20260918 全量实验中完整保存的 buggy 侧记录。
- 离线核对：95 组验证→下一轮规划记录，对应 285 份验证、规划和生成提示词。
- 真实对照：django-10914、django-11019、django-11039 的首轮未接受检查点，每例四组，最终 12/12 完成。
- 根据记录完整性、当前候选一致性和实例顺序选择，没有读取官方标签或 fixed。三例均来自 Django，是开发诊断，不是盲测或全量无退化证明。
- 模型 deepseek-v4-flash，temperature=0.1，max_tokens=4096，thinking=disabled。三个实例并行，同例各组串行，组间顺序轮换。
- 正式方法的三个候选、五轮上限、接受门禁和排序均未修改；新代码仅供实验，不被正式流程导入。

原流程执行严格验证，再用真实控制器构造的新反馈调用规划器。只去重版本把完全相同的重复 JSON 字符串放入共享表，验证其可逐字还原。合并版本在一个请求中提供完整验证和规划上下文，要求同时返回原验证结果与 semantic_delta.v2。

合并输出缺少合法计划时，保留实际验证门禁，退回原规划器；回退调用计入成本。这是“完整上下文联合请求”原型，并不是精简上下文或删除证据。

## 离线结果

| 提示词 | 数量 | 字符数减少 |
| --- | ---: | ---: |
| 下一轮规划 | 95 | 3.58% |
| 候选生成 | 95 | 2.62% |
| 严格验证 | 95 | 0.054% |

285/285 份压缩结果都能逐字还原，总字符数减少约 2.23%。这只证明信息保存，不保证模型理解一致，也不能将字符数等同于 token 或金额。

95 组中，21 组的验证候选与下一轮规划候选文本不同，不能直接沿用针对旧候选的计划。另有 10 组规划反馈明确记录 RESTORE_PARENT。其他差异可能涉及续跑覆盖历史记录，尚未逐例归因，不能统一称为回退。这要求合并路径核对具体候选身份。

## 真实请求结果

表中包括各组所有成功返回的请求；失败 HTTP 尝试另列。已成功的相同请求在补跑中直接复用。

| 版本 | 成功调用数 | 输入 token | 输出 token | 合计 token | 相对原流程 | 回退规划器次数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原流程 | 6 | 41,982 | 3,666 | 45,648 | — | 0 |
| 只去重 | 6 | 41,788 | 2,209 | 43,997 | −3.6% | 0 |
| 只合并 | 4 | 45,649 | 3,176 | 48,825 | +7.0% | 1 |
| 去重并合并 | 6 | 60,783 | 2,251 | 63,034 | +38.1% | 3 |

**去重的直接输入节省仅为 0.46%。** 原流程响应含 1,453 个推理 token，去重组没有；不能把合计 token 减少 3.6% 全部归因于压缩。两组在三例中的验证提示词逐字一致，却给出不同判定，表明采样或服务端波动不可忽略。

只合并虽然将六次成功调用减到四次，但输入与总 token 增加。去重并合并的三例均需额外调用规划器补齐计划，未节省调用。减少请求数并不自动降低按 token 计费的成本。

各组缓存命中不同，补跑也改变了时间与缓存条件；没有配置供应商真实单价，**货币费用总额未知**，不能据此断言账单增减多少。本轮不作统计显著性或严格因果归因。

## 请求故障和费用记录

两条短探针均成功，但长请求曾返回 HTTP 403。后续错误记录明确出现 insufficient_user_quota，同一长请求改用第二个接口成功。最后仅使用现有第二接口补齐缺失步骤，正式密钥池未修改。

四组累计 49 次 HTTP 尝试，22 次成功、27 次 HTTP 错误；探针及单独定位请求在 probe_cost、diagnostic_cost 另记，不能遗漏到整个验证任务开销之外。部分早期 403 尚未保存细分原因，不能逐条断言原因一致。缺少用量的失败金额保持未知，不记作免费。

尽管请求携带关闭推理设置，部分响应仍报告 reasoning_tokens。不能保证供应商每次都执行相同的无推理路由。账本不记录密钥。
