# 环境故障 API 止损修复

## 已修改并验证

本地环境异常使用 InfrastructureUnavailableError，在容器 reset/clean、候选同步等测试前阶段失败时保存 infrastructure_pause.json 并向外传播。单个实例记录 PAUSED_INFRA，不继续验证、seed 切换或备用适配，不写完成断点。批处理结束以非零退出，避免顺序脚本把暂停当成完成。其他实例可以继续。

断点恢复时不复用含明确 Git 锁故障的执行结果。规则不把一般 ModuleNotFoundError、fixture 错误、AssertionError 或测试超时一概当作基础设施故障，以免阻断合法测试修复。

模型响应允许原有输出额度提升；已经达到配置上限仍被截断时抛出 LLMUnavailableError，沿既有 API 暂停路径停止，避免无限付费重试同一上限。网络/限流的既有重试保留。截断暂停目前沿用 API 暂停状态，可能暂停同批后续请求；没有声称它是账户故障。

远端检查时发现新增的独占实例锁、受限 checkout 恢复和 RuntimeInfrastructureError 已由另一份修改加入。没有覆盖这些修改。只新增截断上限止损及对应测试，原文件备份在远端 .runtime/cost_guard_patch。远端现有基础设施测试涵盖故障不进入语义反馈、旧缓存失效、重启先于锁隔离、有限恢复、环境激活失败。

## 额外成本检查

已确认接受后停止当前 seed，最后一轮不再生成下一候选；三个 seed 仍独立运行，这是当前算法候选池设计，没有改成首个接受就全局停止。已有成功步骤通过断点复用；API 记账写入失败不会重新发送已成功响应。

仍可研究的消耗：无效 Delta 后代码没变可能再验证；协议审核是单独模型调用；网络错误会重复提交输入。前两项涉及算法/证据变化，本轮没有删除。网络请求超时后供应商是否已计费，无法从本地错误数确定。截断止损已处理；空响应和网络持续重试仍遵循现有配置，不能称所有异常成本已消除。

远端生成故障历史数量不能直接换算为可节省金额，账本缺少定价及部分失败 usage。

## 使用边界

修改对新进程生效，已运行的 Python 进程不会自动加载。此次未自动重启或补跑历史实验，也没有删除容器锁。PAUSED_INFRA 必须先修环境再 resume；否则仍会再次暂停。当前代码修复可能触发既有实现版本断点校验，不应未经核对直接让旧全量全部重算。
